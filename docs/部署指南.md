# 部署指南

一台新的 Debian 12 服务器，从零到能发信，一条命令。本文档对应 `deploy/install.sh`。

---

## 一、先选场景

| 场景 | 用什么 |
|---|---|
| 全新服务器，不要旧数据 | `install.sh` |
| 换机器，要把联系人/模板/任务带过去 | 旧机器 `migrate.sh export` → 新机器 `install.sh --restore --env-file` |
| 同一台机器重装/换 IP | 直接重跑 `install.sh`，它会识别已有安装并按「修复」处理 |
| 只想看看会做什么 | 加 `--check`，不改动任何文件 |

---

## 二、前置条件

**服务器**：Debian 12，2 核 2G 起步（构建时内存吃紧，低于 1G 会被 OOM 杀），磁盘至少 5G 空闲。root 权限。

**网络**：
- 入站放行 **22 / 80 / 443**
- **不要开 25 端口**：发信全走邮箱服务商的 465/587，开放 25 只会招扫描
- 出站确认 465 / 587 没被安全组拦（多数云厂商默认放行）

**如果要用域名**：先把 A 记录指向这台机器，等解析生效再跑脚本。用 IP 则跳过。

**需要准备**：一个邮箱地址（既做管理员账号，也用于证书到期通知）。

---

## 三、全新部署

```bash
# 1. 上传项目（整个目录，含 app/ 与 deploy/）
scp -r ./mailer-project root@<新IP>:/root/mailer-src

# 2. 先体检，确认没坑
cd /root/mailer-src
sudo bash deploy/install.sh --ip <新IP> --email you@example.com --check

# 3. 确认无误后正式执行
sudo bash deploy/install.sh --ip <新IP> --email you@example.com
```

用域名就把 `--ip <IP>` 换成 `--domain mail.example.com`。

跑完会打印面板地址和初始密码。**这个密码只显示一次**，同时存在 `/etc/mailer/initial-password`，登录后删掉该文件。

### 参数一览

| 参数 | 说明 |
|---|---|
| `--ip <IP>` / `--domain <域名>` | 二选一，必填。决定证书类型 |
| `--email <邮箱>` | 必填。管理员账号 + 证书通知 |
| `--check` | 只体检并打印计划，不改系统 |
| `--skip-cert` | 不签证书，跑在 HTTP 上（内网/调试） |
| `--restore <dump>` | 装完恢复一份备份 |
| `--env-file <env>` | 沿用旧机器的密钥（迁移必用） |
| `--skip-build` | 代码没变时跳过构建，只重启 |

## 四、迁移（换机器）

### 旧机器上导出

```bash
cd /root/mailer-src
sudo bash deploy/migrate.sh export
```

会短暂停掉 worker（避免导出到一半有写入），导出完自动拉起。产出 `/root/mailer-migrate-<时间>.tar.gz`，包含三样：

- `db.dump` —— 数据库
- `uploads.tgz` —— 附件（没有则为空）
- `mailer.env` —— **CRED_KEY / JWT_SECRET / 管理员密码哈希**

### 传到新机器并安装

```bash
# 传项目 + 迁移包
scp -r ./mailer-project root@<新IP>:/root/mailer-src
scp /root/mailer-migrate-*.tar.gz root@<新IP>:/root/

# 新机器上
cd /root/mailer-src
sudo bash deploy/migrate.sh verify /root/mailer-migrate-*.tar.gz    # 可选，先验包
mkdir -p /root/migrate && tar xzf /root/mailer-migrate-*.tar.gz -C /root/migrate

sudo bash deploy/install.sh --ip <新IP> --email you@example.com \
  --restore /root/migrate/db.dump \
  --env-file /root/migrate/mailer.env
```

**为什么要带 `mailer.env`**：里面的 `CRED_KEY` 是 SMTP 密码的唯一解密密钥。只恢复数据库、不带这个文件，新机器上一个发件账号都发不出去——密码解不开。

恢复完成、确认新机器正常后，删掉两端的迁移包：

```bash
sudo rm -rf /root/mailer-migrate-*.tar.gz /root/migrate
```

## 五、脚本到底做了什么

13 步，每步都会打印结果：

| # | 步骤 | 关键点 |
|---|---|---|
| 1 | 系统依赖 | nginx / postgresql / python3-bcrypt |
| 2 | Node 22 + pnpm 9 | 官方 tarball 解压到 `/usr/local`，不污染系统包 |
| 3 | 用户与目录 | `mailer` 系统用户、`/opt/mailer`、`/etc/mailer` |
| 4 | 数据库 | 建角色与库，密码写 `/etc/mailer/db.pass`（600） |
| 5 | 环境变量 | `JWT_SECRET` / `CRED_KEY` 各随机 32 字节 |
| 6 | systemd + 运维脚本 | 备份、恢复、证书钩子、journald 限容 |
| 7 | 代码部署 | tar 管道复制，排除 node_modules 与本机构建产物 |
| 8 | 构建 | 失败即中止并打印日志，不静默跳过 |
| 9 | 数据恢复 | 仅 `--restore` 时执行，先备份当前库 |
| 10 | 迁移 | **先恢复再迁移**，保证 schema 与代码版本一致 |
| 11 | 证书 | 装 certbot venv（apt 版本不支持 IP 证书），申请并配续期 |
| 12 | nginx + 启动 | 先 HTTP 引导态签证书，成功后切 HTTPS |
| 13 | 自检 | 首页 200 / `db:ok` / 未登录 401 / 凭据可读 |

### 两个刻意的设计

**证书失败不中止部署。** 域名没解析好、80 被安全组挡住，这些都很常见。脚本会保持 HTTP 访问、把 `APP_URL` 回退成 `http://`（否则 Cookie 带 Secure 会登不进去），并提示怎么修。修好后重跑即可，已完成的步骤不会重复。

**恢复必须在迁移之前。** 反过来做，备份里的旧 schema 会覆盖掉刚建好的新表。

## 六、部署完必须做两件事

### 1. 单独保存 `mailer.env`

```bash
sudo cat /etc/mailer/mailer.env
```

存到密码管理器或离线介质。里面三样东西：

| 字段 | 丢了会怎样 |
|---|---|
| `CRED_KEY` | **所有 SMTP 密码永久解不开**，只能重新录入每个账号 |
| `JWT_SECRET` | 所有登录会话失效，重新登录即可，不影响数据 |
| `ADMIN_PASSWORD_HASH` | 可以重设，不致命 |

只有 `CRED_KEY` 是不可再生的。备份只覆盖数据库和附件，不含这个文件。

### 2. 改管理员密码并删除临时文件

```bash
sudo bash -c '
read -rsp "新密码: " P; echo
H=$(python3 -c "import bcrypt,sys;print(bcrypt.hashpw(sys.argv[1].encode(),bcrypt.gensalt(12)).decode())" "$P")
sed -i "s#^ADMIN_PASSWORD_HASH=.*#ADMIN_PASSWORD_HASH=$H#" /etc/mailer/mailer.env
systemctl restart mailer-api
rm -f /etc/mailer/initial-password'
```

改密码不会让已登录会话失效（会话签名用 `JWT_SECRET`，与密码无关）。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 证书签发失败 | 域名没解析 / 80 端口被挡 / IP 不是本机出口 IP | 修好后重跑脚本，站点在 HTTP 上仍可用 |
| `pnpm install` 失败 | 内存不足（<1G） | 加 swap：`fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile` |
| Node 下载失败 | 官方源不可达 | 脚本会自动切 npmmirror；仍失败则 `NODE_VERSION=x.y.z` 指定版本 |
| 端口 80 被占用 | 有其他 web 服务 | 脚本会提示进程名，先停掉 |
| 迁移后发件失败 | 没带 `--env-file`，`CRED_KEY` 是新的 | 重新用旧 env 跑一次，或在面板重新录入所有 SMTP 密码 |
| 迁到新机器后追踪链接指向旧地址 | `APP_URL` 没更新 | 重跑脚本会自动对齐（`step_align_env`） |
| 面板能开但一直转圈 | API 起了但连不上库 | `journalctl -u mailer-api -n 50` |

## 八、文件清单

```
deploy/
├── install.sh              一键部署（本文档的主角）
├── migrate.sh              迁移导出 / 验包
├── provision.sh            系统层初始化（被 install.sh 调用，也可单独跑）
├── backup.sh               每日备份 → /usr/local/sbin/mailer-backup
├── restore.sh              恢复（默认演练模式）→ /usr/local/sbin/mailer-restore
├── cert-hook.sh            证书续期钩子 → /usr/local/sbin/mailer-cert-hook
├── upgrade.sh              代码升级
├── mailer.env.example      环境变量说明
├── nginx/
│   ├── mailer.conf           引导态（HTTP + ACME，签证书前用）
│   └── mailer.template.conf  正式态（HTTPS，`__CERT_NAME__` 由脚本替换）
├── systemd/
│   ├── mailer-api.service
│   └── mailer-worker.service
└── tools/                  测试与调试脚本（不参与部署）
```

部署后的运行时目录：

| 路径 | 内容 |
|---|---|
| `/opt/mailer` | 应用代码（`apps/api`、`apps/web`） |
| `/opt/mailer/shared/uploads` | 附件 |
| `/opt/mailer/shared/certs` | 证书副本（面板读它判断到期） |
| `/etc/mailer/mailer.env` | 全部密钥与配置（640 root:mailer） |
| `/etc/mailer/db.pass` | 数据库密码（600） |
| `/var/backups/mailer` | 每日备份，保留 14 天 |

## 九、部署后第一次使用

1. 打开面板，用邮件里给的管理员账号登录
2. **发件账号** → 添加 SMTP 账号。密码填「授权码 / 应用专用密码」，不是邮箱登录密码
3. 点「测试连接」→ 通过后点「发测试信」发给自己
4. **联系人** → 导入 CSV/XLSX，向导会先预览再确认
5. **邮件模板** → 新建模板，用双模式编辑器
6. **群发任务** → 四步向导建第一个任务，先发 5 个人试试

**第一封信务必发给自己并检查收件箱。** 进垃圾箱的话，先查 SPF/DKIM/DMARC 是否配齐（`docs/运维手册.md` 第二节）。
